# Private preview feedback — synthetic data only

Reproduce with generated synthetic messages where possible. Send this manually and
privately to the owner through a channel the owner approves. Nothing is automatically
collected or uploaded. Do not contact other testers or forward the application.

```text
Application version / About Build:
Candidate identifier or owner-supplied ZIP checksum:
Windows version / architecture:
Display scaling/theme, if relevant:
What I was trying to do:
What happened:
What I expected:
Reproduction steps:
Synthetic message type/count and scope (no real contents):
Frequency (once / sometimes / every time):
Does this block further testing? How?
Does it recur after closing and reopening?
Safe fixed error/status category, if shown:
Optional reviewed synthetic-only screenshot / Activity Log excerpt:
Optional general usability feedback:
```

**Never submit PHI, real HL7 patient messages, credentials, secrets, sensitive
network addresses, production filenames/endpoints, unreviewed crash dumps or temporary
snapshots.** Do not attach workspace/configuration folders or unreviewed logs.
Screenshots can expose titles, paths, message values and endpoint details; inspect
and remove sensitive information first. A safe Activity Log category/count is not
permission to share arbitrary output or other application content. Leave optional
evidence out if uncertain, and describe the issue using synthetic steps instead.

Record expected and actual results separately. A useful usability report can simply
identify where wording, focus, layout or the workflow was confusing; a screenshot is
optional. See [TEST-SCENARIOS](TEST-SCENARIOS.md) for small starting tasks.
