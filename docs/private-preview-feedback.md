# Private preview feedback — synthetic data only

Send feedback manually and privately to the person who supplied the approved preview.
Nothing is collected or transmitted automatically. Copy this template:

```text
Message Workbench build ID (Help → About):
Windows version and architecture:
What I was trying to do:
Synthetic input type and approximate message count:
Steps to reproduce:
Expected behavior:
Actual behavior:
Error/status category, if shown:
Does it happen again after restarting?
Additional notes:
```

Use synthetic data throughout the initial preview. Do not send real HL7 messages,
PHI, credentials, endpoint secrets or production filenames. Do not attach raw crash
dumps, temporary storage, workspace folders or unreviewed logs. Review screenshots
for patient values, titles, paths and endpoint information before sharing.

Activity Log's fixed categories/counts can help describe events; they do not authorize
sharing other application content. If Build says unavailable, quote that honestly and
use the owner-supplied build/provenance identifier or archive checksum. Do not guess a
commit. Preserve desired drafts and describe their state without including content.
